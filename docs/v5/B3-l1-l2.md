# v5 B3 — L1/L2 merge: one definition per name, no root pins, removed aliases, renamed search files

Status: implemented and measured 2026-10-28 on `feat/v5-b3-l1-l2` (base `v5` @ `4e46d0dc`). Design: SPEC § 4 (vault). Measured facts behind the design: `docs/v5/B3-inventory.md`. Consumer side: `lemon-templates-api` `feat/v5-b3-l1-l2` (base `v5` @ `6aa50073`). User-facing changes: `HOW_TO_UPGRADE_V5.md` § 9.

## Scope

- **One definition per name.** The 20 L1/L2 pair names (13 types, `$T`, `parseListParam`, `parsePaginateParam`, `onlyDefined`, `sourceToItem`, `Filter`, `marshal`) plus `AggrResult` are each declared in one file. The content is the copy the root already exported (SPEC § 4.2); the file is the lower folder (`helpers/`, `common/`, `extended/abstract-service.ts`). The other file re-exports it, so every deep path keeps its names.
- **Root pins removed.** `src/index.ts` has no `export type {` line and 3 `export {` lines (`lib, tools`, `withBrowserCache`, `$ES6Routed`). Root names 294 → 294.
- **Removed members.** `MyCoreService.isUseSssion()`, `Utilities.crypto()` (+ inner `encrypt`/`decrypt`), `credentials()` (`environ.ts`), `AbstractProxy.getCurrentIdentity$()`, `IdentityToken.iid`. Kept with reasons in SPEC § 4.5: `CoreManager.insert`, the `fetchIdentityAccess`/`_identity`/`getIdentity$` cluster, `loadEnviron`.
- **Search files renamed.** `cores/elastic/elastic6-service.ts` → `os2-service.ts`, `elastic6-query-service.ts` → `os2-query-service.ts` (and the 2 specs). The old names are 1-line `export *` shims for `./dist/*` during v5.
- **P1.** 4 of the 5 identical-body overrides removed (`OS2Service.describe`/`createIndex`/`search`, `OS2Instance.describeIndex`); `OS2Instance.options` kept (see Deviations).

## Choices (SPEC left open)

- **`$T` assembly.** The L2 `S2`/`SS` were written on top of the L1 ones (`_T.S2(v, def, ' ')`, `_T.SS(v)`). In one object they cannot call themselves, so the L1 bodies stay as module-local `_S2`/`_SS` and the L2 members call them. Every input gives the same result as the old root `$T` (the L2 `S2` keeps a default `def = ''`, as the L1 parameter had, so `def = null` behaves as before).
- **`N` signature.** L2 `(v: boolean | number | string | unknown, def = 0)` taken as is (the root type). The body calls the local `_N` directly (same result as the L2 → L1 `N` chain).
- **Re-export placement.** `sourceToItem` is re-exported right after the `../abstract-service` import block; `Filter`/`marshal` as `import` + `export type { Filter }` / `export { marshal }` (`isolatedModules`-safe).
- **lemon-model re-export in `extended/cores/types.ts`** written as `export type { CoreModel, View, Body } from 'lemon-model'` (one line, no local import).
- **Spec assertions.** No `S2` 3-argument or `SS(v, def)` assertion existed, so nothing had to change; 5 assertions were added inside the existing `$T` test to pin the merged behaviour (no new test, count unchanged).
- **`dup-decls.cjs`** checks 21 names (the 20 pair names + `AggrResult`) for exactly one declaring file, and fails on any duplicate outside the 5 L1-only names. **`l1l2-probe.cjs`** resolves deep paths by package self-reference (`require('lemon-core/<path>')`), so it goes through the `exports` map like a consumer.
- **Comments.** Comments that would contain `isUseSssion`/`$X`/`elastic6` were worded without the literal, so the name-trace greps stay at 0 / shims only.

## Deviations from SPEC § 4

1. **`OS2Instance.options` is not removed (P1, § 4.7).** Its body equals the base getter, but its declared return type is `OS2Option` (base: `OS2BaseOption`). Removing it would widen the public type of `OS2Instance.options` in the `.d.ts`. Kept with a 1-line comment, like the re-declared fields § 4.7 keeps. 4 of 5 removed.
2. **Spec fixture renamed.** `grep -rln elastic6 src` = shims only (gate 9 / PLAN T7-6) needed the fixture name in `os2-service.spec.ts` changed, so `data/dummy-elastic6-data.yml` became `data/dummy-os2-data.yml` (content unchanged; `data/` is not published). Also the local variable `elastic6` in `lambda-dynamo-stream-handler.spec.ts` and 2 comments. SPEC § 4.6 listed only the import lines.
3. **templates-api spec file deleted, not edited.** `transformer.spec.ts` had one test, and it used `$X`; an empty `describe` fails under jest. Deleting the file also drops its `viewTransformerModel` entry from the tracked `src/generated/field-registry.ts` (regenerated by `fields:gen` on build/test).
4. **SPEC § 4.0 "deep paths 11":** `lemon-core/dist/helpers` (directory) is not one of them — it does not resolve since B1; the 11 checked are the resolving rows of inventory § 2.4 (`…/helpers/types`, `…/helpers/helpers`, `…/helpers/index`, `…/common/test-helper`, `lemon-core/testing`, `…/extended/cores`, `…/extended/cores/commons`, `…/extended/cores/types`, `…/extended/cores/abstract-services`, `…/extended/abstract-service`, `…/cores/config/config-service`).
